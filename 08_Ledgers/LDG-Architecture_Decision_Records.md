# Architecture Decision Records (ADR)

This ledger records architectural decisions that govern vault topology, ingestion invariants, multi-agent synchronizations, and cognitive memory tiering across the Narrative Framework.

> **Whose decisions are these?** This ledger records the **framework's** architecture. Your own story and curator decisions belong in `memory/decisions/`: record them with `narr decide "<title>"` (and supersede with `--supersedes`).

---

## ADR-001: Separation of Canon Truth from Creative Divergence
- **Status:** Accepted (2026-10-15)
- **Context:** Creative fanfiction projects historically suffered from "fanon bleed", where creative hypotheses contaminated factual canon references.
- **Decision:** Strictly isolate pure canon inside `01_Canon_and_Divergence/Baselines/` (`CAN-` prefix) grounded in immutable raw sources (`SRC-` prefix). All narrative divergences must be explicitly declared in `01_Canon_and_Divergence/PODs/` (`POD-` prefix).
- **Consequences:** Linters reject any creative speculation in `CAN-` files. Creative changes require an explicit POD anchor.

---

## ADR-002: Dual Agent Harness Topology (.agents and .claude)
- **Status:** Accepted (2026-10-15)
- **Context:** Different AI coding harnesses (Google Antigravity, Claude Code) read skills from different standard root locations.
- **Decision:** Maintain identical skill catalogs in both `.agents/skills/` and `.claude/skills/`, enforced by `narr doctor` multi-agent parity verification.
- **Consequences:** Zero drift between agent harnesses; complete tooling portability.

---

## ADR-003: Unified CLI Architecture (narr)
- **Status:** Accepted (2026-10-16)
- **Context:** Legacy framework relied on multiple disjointed python scripts (`vault_lint.py`, `bible_crosscheck.py`, `catalog_manager.py`).
- **Decision:** Consolidate all vault operations into a single modular CLI tool (`narr`) installed via `pyproject.toml` with subcommands (`doctor`, `lint`, `crosscheck`, `ingest`, `new`, `preset`, `prompt`, `pipeline`).
- **Consequences:** Standardized testing, robust packaging, streamlined terminal operations.

---

## ADR-004: Right-Sized Ingest Consolidation
- **Status:** Accepted (2026-10-17)
- **Context:** Naive 1:1 source-to-baseline ingestion created hyper-fragmented micro-stubs (108 stubs), causing severe context-window thrashing and tool-hopping overhead. Monolithic mega-files (>50 KB) cause token exhaustion.
- **Decision:** Mandate a "Goldilocks Zone" for canon baselines: 3 KB to 15 KB (approx. 80-220 lines), consolidating 2 to 5 versioned or closely related sources per baseline.
- **Consequences:** High informational density, reduced tool hops, unified topic context. Multi-source baselines verify quotes against the union of cited sources.

---

## ADR-005: 4-Tier Cognitive Memory & Knowledge Governance
- **Status:** Accepted (2026-10-17)
- **Context:** Long-horizon narrative generation and multi-chapter authoring require seamless coordination between instant operational state, episodic session logs, structured canonical truth, and evolutionary framework governance.
- **Decision:** Establish a formal 4-Tier Cognitive Memory Hierarchy synthesized from production multi-agent memory frameworks:
  1. **Tier 1 (Ephemeral Working Memory):** `memory/hot.md` (active sprint goals, immediate blockers, context limits).
  2. **Tier 2 (Episodic Session Memory):** `08_Ledgers/LDG-Session_Handoff.md` and `LDG-Canon_Ingest_Log.md` (append-only timeline of agent actions, verification proofs, and handoff tokens).
  3. **Tier 3 (Semantic & Structural Memory):** `01_Canon_and_Divergence/` and `02_Story_Bible/` (persistent wikilinked entity graphs, RPG status sheets, and consolidated baselines indexed in SQLite FTS5).
  4. **Tier 4 (Evolutionary Meta-Governance):** `.agents/skills/framework-sync-governance/` and `Meta/Presets/` (bidirectional synchronization between specialized story vaults and the neutral framework core).
- **Consequences:** Eliminates context drift across multi-session authoring, ensures zero-regression transitions, and guarantees architectural integrity.

## ADR-006: Native Link-Following Renaming & Undo Journal (`narr mv`)
- **Status:** Accepted (2026-10-17)
- **Context:** In ongoing narrative projects, renaming characters, factions, or power systems manually resulted in widespread broken ``wikilinks``.
- **Decision:** Implement `narr mv <old> <new>` with global link following across all markdown files and an atomic rollback journal stored in `.narr/mv_journal.jsonl`.
- **Consequences:** All inbound references are updated automatically; any rename can be undone with 100% fidelity using `narr mv --undo`.

## ADR-007: Deterministic Consolidation Leads (`narr candidates`)
- **Status:** Accepted (2026-10-17)
- **Context:** Fandom wiki inboxes and creative worldbuilding often introduce near-duplicate entities with minor title variations.
- **Decision:** Implement `narr candidates` using mathematical Jaccard token overlap ($\ge 0.60$) between entities of the same type, detecting stale links to superseded pages, and surfacing declared contradictions.
- **Consequences:** Provides actionable, evidence-based consolidation leads without autonomous destructive merges.

---

## ADR-008: Retrieval Quality Benchmarking (`narr eval`)
- **Status:** Accepted (2026-10-17)
- **Context:** As vaults expand to hundreds of pages, RAG retrieval quality for chapter drafting risks degradation without quantitative measurement.
- **Decision:** Adopt `Second_brain`'s evaluation framework (`eval/queries.yaml` and `eval/runs.jsonl`), calculating Recall@k, MRR, Hit Rate, and NDCG@k via `narr eval`.
- **Consequences:** Guarantees that search recall remains $\ge 0.80$; warns when hybrid vector indexing or FTS5 re-weighting is needed.

---

## ADR-009: Network-Confined Source Clipping & Offline Mirroring (`narr clip` & `narr import`)
- **Status:** Accepted (2026-10-17)
- **Context:** Ingesting fandom wiki lore or downloaded novel chapters required tedious manual file creation and formatting.
- **Decision:** Add `narr clip <url>` (with SSRF protection and tracking parameter removal) and `narr import <folder>` (offline folder mirror with SHA-256 deduplication).
- **Consequences:** Web and offline sources are staged automatically into `01_Canon_and_Divergence/Sources/inbox/` with `.meta.json` sidecars, preventing duplicate inboxes.

---

## ADR-010: Budget-Constrained Multi-Tier Operational Memory Brief (`narr memory brief`)
- **Status:** Accepted (2026-10-17)
- **Context:** Large LLM context windows often get bloated by raw file dumps during session initialization.
- **Decision:** Implement `narr memory brief` enforcing a strict character budget (<9,000 chars) that synthesizes working memory (`hot.md`), active plot threads, primed Chekhov guns, open decisions, pending inbox items, and vault health.
- **Consequences:** Any agent cold-starts with perfect situational awareness in under 1,500 tokens.

## ADR-011: Deterministic Vault Guard Beyond the Linter (`tools/vault_audit.py`)
- **Status:** Superseded by ADR-015 (2026-10-19)
- **Context:** `narr lint` and `narr crosscheck` passed while baselines held unsourced numbers, quotes did not come from the cited source, tables had broken columns, scopes were undefined and ledgers held sample rows.
- **Decision:** Ship `tools/vault_audit.py`. It fails on dead wikilinks, frozen-source SHA mismatch, italic quotes absent from the cited sources, `uid` not matching the filename, undefined `scope`, table column mismatch, ledger rows for unwritten chapters, absolute local links and CJK outside Sources.
- **Consequences:** Run it with `narr lint` before every commit. `tools/build_atlas.py` rebuilds the Atlas so the hub cannot drift.

## ADR-012: Content-Level Multi-Agent Parity (`narr doctor`)
- **Status:** Accepted (2026-10-18)
- **Context:** The parity check compared only rule file names, so a drifted skill passed as "Synchronized".
- **Decision:** `narr doctor` compares rules and skills by relative path and by line-ending-insensitive SHA-256, and names the drifting files.
- **Consequences:** Edit a skill in both `.agents/` and `.claude/` in the same change, or the check fails.

## ADR-013: Author Voice Reaches the Chapter Prompt
- **Status:** Accepted (2026-10-18)
- **Context:** `narr prompt render write-chapter` ignored `context/author_voice.md`, and spent its token budget on frontmatter.
- **Decision:** The prompt includes `context/author_voice.md` as a priority-1 section and strips YAML frontmatter from every injected note.
- **Consequences:** The voice contract shapes every drafted chapter. Keep the file short; it is truncated at 2,200 characters.

## ADR-014: Presets Register Their Page Types
- **Status:** Accepted (2026-10-18)
- **Context:** Presets introduced page types (for example a profession or a theory) that `narr lint` rejected until the curator edited `vault.yaml` by hand.
- **Decision:** A preset manifest may list `custom_types`. `narr preset apply` appends the missing ones to `vault.yaml` and reports them. The merge is idempotent.
- **Consequences:** Applying a preset is enough to make its seeded templates lint-clean.

## ADR-015: Centralized Guard SSOT in `narr.checks` and Thin Audit Wrapper
- **Status:** Accepted (2026-10-19)
- **Context:** ADR-011 created `tools/vault_audit.py` as an independent script outside the core CLI engine, duplicating verification logic and diverging from `narr lint` / `narr crosscheck`.
- **Decision:** Promote all vault invariant checks (VAL033–VAL038) directly into `src/narr/checks.py`. Refactor `template/tools/vault_audit.py` into a thin client delegating directly to `narr.checks.run_all_checks`. Supersede standalone guard logic in ADR-011.
- **Consequences:** Single Source of Truth for all ontological rules across CLI, test suites, and template helper scripts.

## ADR-016: Single Path Gate and Connect-Time Network Validation
- **Status:** Accepted (2026-10-22). Extends ADR-009; contradicts no earlier ADR.
- **Context:** An independent audit found the SEC-01 path guard was never called by production code, and reproduced writes, moves and deletions outside the vault through `narr mv`, `promote`, `preset apply/remove --force`, `narr new` with a shared template, and `ingest skip`. The web clipper validated only the first URL, so a redirect or DNS rebinding reached loopback and cloud-metadata addresses. Text from `Sources/` entered prompts with no data/instruction boundary.
- **Decision:** (1) `Vault.resolve_path` / `Vault.safe_rel` are the only door for filesystem operations that involve a user- or data-derived path, including paths read back from on-disk records such as the rename journal and the applied-presets record: they reject parent segments, absolute paths outside the vault, UNC, drive-relative and alternate-data-stream forms, NUL bytes and symlinks or junctions. (2) Identifiers (source ids, preset names, slugs, prefixes) are validated as plain names, never accepted as paths (accents are allowed); only `import <folder>` and `capture <file>` read outside the vault and never modify it, and `prompt render --output` writes the one file the operator names. (3) No command renames, moves, deletes or rewrites anything inside `Sources/` except the ingest workflow itself (`capture`, `clip`, `import`, `ingest close/skip`); `narr mv` refuses to rename into, out of or inside it and skips it when rewriting links. (4) Presets and page templates are validated as a whole before the first write; entries of an on-disk record that fail validation are skipped with a warning. (5) `narr clip` resolves each host once at connect time and requires every address to be globally routable (allow-list), for the first request and every redirect; at most 5 redirects, http(s) only, a 30 s total deadline covering connect, headers and body (DNS lookup itself is not bounded), proxies disabled. (6) The video downloader is dispatched only for exact video-site hosts and restricted to that site's extractor. (7) Credentials in URLs are refused and credential-bearing query parameters are never stored. (8) Source text and source titles in prompts are wrapped or neutralised as untrusted data. (9) File enumeration never follows symlinks or junctions. An allow-list architecture test fails when a new module mutates files without review; it checks that the confining functions are called, not that they guard every write.
- **Consequences:** Hostile arguments, manifests and templates fail with a clear error and no partial effect. Residual risk, accepted and documented: the video downloader performs its own networking, so its addresses cannot be pinned. Users behind an HTTP proxy must allow direct connections for `narr clip`. Stale ADR citations in CLI help text remain a follow-up for the CLI audit area.

## ADR-017: Configuration Contract and Check-Code Registry
- **Status:** Accepted (2026-10-22). Implements as a warning the identity rule that ADR-011 stated (ADR-011 is superseded by ADR-015, which keeps the guard in `narr.checks`); contradicts no other ADR.
- **Context:** An independent audit found `vault.yaml` budgets silently ignored (the checks read other key names), keys nobody reads, `narr doctor` unable to fail, two continuity gates with different code lists (one listing codes that nothing emits), about twenty check codes never seen to fire, and several false negatives (empty required fields, duplicate `uid`, short or curly-quoted citations, sandbox links written by name, scope visibility never applied to links).
- **Decision:** (1) The key names shipped in `vault.yaml` are canonical (`agents_md_max_lines`, `hot_memory_max_lines`, `operational_file_max_bytes`); the earlier short names stay accepted as aliases and the canonical name wins. A budget must be a positive integer (VAL039, error) and an unknown key under `budgets` is a warning (VAL039). (2) `narr.config_contract` registers every shipped key as read by code, descriptive, or reserved for a named audit area; a static test fails when the shipped configuration and the registry disagree in either direction. (3) `narr doctor` exits 1 when any diagnostic fails, in text and JSON mode. (4) `CONTINUITY_CODES` is the single definition of the codes gated by `narr crosscheck` and `narr pipeline run crosscheck`; VAL020 and VAL029 are retired because no check ever emitted them. (5) Every code the checks can emit has a firing test (bad input fires with the documented severity, good input stays quiet) and a meta-test fails when a code has none. (6) New checks: VAL001 also fires on empty required fields; VAL040 (error) duplicate `uid` (a chapter and its translation in different language folders, archived copies, templates and sandbox notes are not duplicates); VAL041 (warning) `uid` differing from the file name; VAL042 (warning) a link to a page whose scope the linking scope cannot see (Sources, the Atlas, templates, sandbox, `meta` scope and placeholders are exempt); VAL014 resolves the link to the real page; the dead-link check ignores blueprint placeholders; quotations in straight, curly or guillemet marks are verified when they have 12 or more characters or 3 or more words (manuscript chapters keep only the straight form, because a curly or guillemet italic there is a character's thought). (7) New findings other than duplicate `uid` and the strengthened required-field check are warnings, so existing vaults are not suddenly broken; `--strict` turns them into failures.
- **Consequences:** Lowering a budget now makes oversized files fail. `narr doctor` can stop an installer or a publish smoke test. The seed termbase moved from `source_canon` to `fanfic_canon` because the new scope check showed it links to a fanfic-scope character. Reserved keys (prompt budgets, locales, the retrieval-model block, commit policy, the version range) remain unimplemented and are owned by later audit areas. Not covered here: the entity prefix list, one top-level heading per page, flat topology, a real "overdue" computation for the foreshadowing check, and the unparsable-page blind spot of the linter (Area 2).

## ADR-018: Data Integrity — Parse Failures, Frontmatter Emission, Ingest Freeze and Undo
- **Status:** Accepted (2026-10-22). Builds on ADR-016 (path gate) and ADR-017 (check-code registry); contradicts no earlier ADR.
- **Context:** An independent audit found the linter silently dropping pages it could not read, commands writing frontmatter with string formatting (a title with quotes or a line break broke or forged metadata), a YAML alias bomb that stalled the tool, rewrites that converted CRLF to LF and dropped byte-order marks, imports and captures that overwrote existing sources, an `ingest close` that re-hashed a tampered frozen source and duplicated ledger rows, a freeze that was not interruption-safe, and `mv --undo` restoring by line number over the curator's later edits.
- **Decision:** (1) A page the loader cannot read is the lint error VAL043 with the reason (invalid YAML, frontmatter never closed, not UTF-8, aliases, size); it applies to the numbered vault zones, `memory/` and `context/`, not to notes in `docs/`, `Meta/` or at the vault root. (2) Frontmatter is written through YAML-escaped values (quotes, backslashes, control characters, line breaks collapsed to one space) in `narr new` (built-in and custom templates), `chapter new`, `import` and `promote`; the body keeps the title on one line. (3) The loader refuses YAML aliases and merge keys and frontmatter above 64 KB. (4) All data writers use `write_text_atomic` / `write_bytes_atomic`, which preserve an existing file's line endings and byte-order mark, write new files with LF, and sync before the replace; a static test forbids plain `write_text` / `write_bytes` and `open` for writing in every module except the atomic writers and the prompt-render `--output` option; bulk rewrites such as `mv` skip the sync (`durable=False`) because the journal makes them recoverable. (5) An import id that is taken receives a suffix of the first eight hex digits of the content hash; `capture --id` is refused over a frozen id or different inbox content and is idempotent for identical content. (6) `ingest close` is idempotent for a source registered as frozen whose hash matches the record, and refused whenever a frozen-registered file no longer matches its recorded hash (in `Sources/` or in the inbox after an interrupted close); a skipped or half-frozen source is validated and closed normally; the freeze runs registry entry, file move, ledger row, and a repeated close completes any missing step with at most one ledger row per source and hash. (7) `mv` journals carry a pending/done state; `mv --undo` reverts a line only where the file still holds what the rename wrote, refuses everything with a conflict list otherwise, and can undo a pending rename. (8) Promotion keeps an older archive copy under a timestamped name and `chapter new --force` moves the old file to `.narr/trash/`.
- **Consequences:** A vault with unreadable pages now fails `narr lint`. Frontmatter with YAML aliases is rejected. Rewrites keep a vault's own style. Imports, captures and closes cannot destroy evidence. Residual risk, accepted: the search index may still serve stale content for a page that stops parsing (retrieval area); a multi-file rename is recoverable through the journal but not a single atomic transaction.

## ADR-019: Scope-Safe, Self-Healing Lexical Retrieval
- **Status:** Accepted (2026-10-22). Builds on ADR-003 (one CLI: `reindex` is a subcommand of `narr`), ADR-008 (benchmarking) and ADR-018 (data integrity); contradicts no earlier ADR.
- **Context:** An independent audit found that context assembly ignored scopes (sandbox and alternate-universe notes entered a canon context), ignored its token budget, trimmed ledgers by losing their newest rows, and used full-text weights shifted by one column; that the index had no schema version, turned a corrupt file into a traceback, a locked database into an empty result and a page that stopped parsing into stale hits; that punctuation, stopwords, CJK text and the documented `--zone canon` all failed; and that `narr eval` counted skipped queries, double-counted duplicate expectations and could not gate anything. The vault configuration and the `vector` extra also described embeddings that were never implemented.
- **Decision:** (1) Retrieval is lexical: SQLite FTS5 with BM25 (weights title 5, body 1, tags 2, the path column unweighted; ties ordered by path). Vector or hybrid retrieval is not implemented; the `rag:` block in `vault.yaml` was unread and has been removed (decided 2026-10-22: retrieval stays lexical). (2) The index stores each page's scope and status. A viewpoint scope sees the scopes its `can_see` list names (the helper shared with the VAL042 link check; no hierarchy means no restriction); a page without a scope counts as `scopes.default`; superseded pages are never retrieved for drafting. `rag context`, the lore-dossier prompt and the write-chapter prompt use the default scope unless `rag context --scope` chooses another; plain `narr search` is unrestricted, shows each hit's scope, and `--scope` narrows it. (3) Only the numbered zones, `memory/` and `context/` are indexed (the lint's page-zone rule); templates, guides and agent documents are not. A page that stops parsing leaves the index and its stamp is recorded so it is not re-parsed. (4) The index is derived data with `PRAGMA user_version`; a missing, corrupt or older-schema file is deleted with its write-ahead files and rebuilt automatically; `narr reindex` rebuilds on demand; `narr doctor` checks version and integrity; a busy database is a clear error with exit code 1, never an empty result; connections close on every path. (5) Queries are folded, split on any non-word character, stripped of English, Portuguese and Spanish stopwords unless nothing else remains, matched as prefix terms with pages containing every term first and pages containing some completing the list; CJK runs are indexed and queried character by character; the limit is at least 1; `--zone` accepts real directory names in any case and the aliases canon, sources, baselines, pods, bible, continuity, manuscript, craft, ideation, cosmology, ledgers and atlas. (6) The context budget (`--budget`, default `budgets.max_context_tokens`, same estimator as the prompt engine) is allocated by priority: header and tone boundaries, then the character-knowledge, Chekhov and thread ledgers (each keeps its header and its newest rows), then page references cut from the body; the lowest priority is shortened and then removed first, and a context under budget is unchanged. A baseline reference resolves from a wikilink or a bare stem, with or without the `CAN-` prefix, and a missing baseline is named in the context. (7) Evaluation uses the standard definitions: distinct expectations, one rank each; skipped queries are counted apart and excluded from every denominator; expectations match a stem, title or path in any case; per-query `zone` and `type` filters apply; p95 is nearest rank; `--min-recall` exits 1 below the threshold; the shipped `eval/runs.jsonl` is empty and a test pins recall@5 of at least 0.80 on the seed vault. (8) The link graph and `narr related` resolve a link target by file stem, then title, then `uid`, without regard to letter case, so title- and uid-linked pages are not orphans.
- **Consequences:** Context for a canon scene no longer contains sandbox or divergence material and fits the budget it is given; ledgers lose their oldest rows first. An index from an older version is rebuilt on first use. A multi-word query now returns pages with some of its words after those with all of them, so a hit list is longer than before. Page references in a context show body text instead of frontmatter. ADR-008's remark about hybrid vector indexing stays a possible future decision; today the remedy for low recall is better queries, titles, tags and wording. Residual risk, accepted: stopword lists are short and cover only three languages; a context allocation uses a heuristic token estimate, not a model tokenizer.

## ADR-020: Manuscript Pipeline — One Chapter Rule, Exact Paragraph Parity, Termbase and Prompt Budget
- **Status:** Accepted (2026-10-22). Builds on ADR-017 (check-code registry) and ADR-019 (the shared `budgets.max_context_tokens` key); contradicts no earlier ADR.
- **Context:** An independent audit found that the MSC004 parity gate stored markers in a dictionary (a duplicated or reordered `<!-- p:N -->` passed, markers in comments and code fences counted) and silently used a block-count heuristic when the Spanish file had no markers; that prompts, the parity check and the chapter status each selected a chapter file differently (`C01*` also matched `C010`, the first match of an unordered glob won, duplicates were unseen); that a failed `translate check` gave no reason; that termbase cells were split on the pipe of a wikilink alias and the translation prompt cut the termbase at 2000 characters; that output validation missed Spanish preambles, kana and hangul and treated marker disorder as a warning; and that the prompt budget was fixed and `--lang` ignored.
- **Decision:** (1) A file belongs to chapter N when its name is `C`, digits equal to N, then the end of the name or `_` or `-`, then `.md` (`C01_x.md` and `C1_x.md` are chapter 1, `C010_x.md` is chapter 10); several files for one number are an error naming them; `narr.manuscript` owns the rule and the prompts, parity check, lint and chapter status use it. (2) The marker model is the ordered numbers of `<!-- p:N -->` outside frontmatter, fenced code and other comments; a draft must have strictly increasing markers and no empty paragraph; a translation must equal its source marker for marker; when exactly one side has markers the check fails; the block-count heuristic (tolerance 8 or 10 %) applies only when neither side has markers. (3) MSC004 in lint pairs chapters by number and applies the same comparison, still as a warning. (4) `translate check` reports its mode and every diagnostic in text and in JSON (`diagnostics`, `missing_terms`, `leaked_terms`, `marker_mode`); exit codes are unchanged. (5) Termbase cells are split outside wikilinks and unescaped pipes; the translation prompt contains in full every mapping whose pt-BR term occurs in the chapter, then other mappings within the remaining budget share, and a note counting the rows left out. (6) `prompt validate` rejects Spanish preambles beside Portuguese and English ones; one CJK pattern (Han, hiragana, katakana, hangul) serves the lint's VAL010, the validator and `promote`; duplicate or out-of-order markers are errors, a numbering gap and an empty paragraph in a draft are warnings, an empty paragraph in a translation is an error, and a translation without markers is an error when the source has them. (7) `prompt render --budget` defaults to `budgets.max_context_tokens`; mandatory sections (assignment, voice, continuity, tone for writing; source chapter and relevant terms for translating) are never dropped, others are dropped lowest priority first; a budget below one is rejected. (8) `--lang` must equal `locales.publish` (default `es`) and only `es` is implemented; anything else is a clear error; `locales.publish` is now read by code.
- **Consequences:** Chapters whose Spanish file lacks markers, or has a duplicated or reordered one, now fail `translate check` and warn in `narr lint`. Ledger-heavy write prompts shrink when the configured budget is small. Generated output containing kana or hangul now fails VAL010. A multi-file chapter number is a visible error instead of a silent first-match. Residual risk, accepted: the block heuristic remains for marker-less legacy chapters; the Spanish preamble list is short; translation to languages other than `es` is not implemented.

## ADR-021: Agent Harness — Installed Gates, Valid Skills, a Neutral Template and One Memory
- **Status:** Accepted (2026-10-22). Builds on ADR-002 (dual agent harness), ADR-017 (configuration contract) and ADR-018 (data integrity); contradicts no earlier ADR.
- **Context:** An independent audit found that the rules promised gates nothing installed (`narr hook install` did not exist, the hooks folder was ignored by git, no agent settings shipped, and `git.commit_types`, `git.require_lint_pass` and `git.co_author` were read by nothing); that the supposedly neutral template carried another franchise's vocabulary in most blueprints, one rule and several skills, and a skill held the author's personal path; that two skills had invalid frontmatter and almost every description lacked a trigger; that `narr session close` overwrote `memory/hot.md` and dropped the curator's sections while `lessons.md` was never read and the vault shipped the framework's ADRs as if they were its own decisions; and that the rules disagreed (costs and limits were attributed to the wrong Sanderson law, scope lists and prefixes differed between documents, there were two canon authority orders).
- **Decision:** (1) The `narr hook` group installs, shows, removes and runs the gates: `install` merges the agent settings (`.claude/settings.json`) idempotently and sets `core.hooksPath` to the committed hooks folder when the vault is in a git work tree; `status`; `uninstall` removes only narr's entries; `run <event>` is what the settings and git hooks call. (2) Pre-write guard: writes to frozen sources and to `.narr/` are denied with a reason, writes to `context/` ask first, paths outside the vault are not judged, and a missing or broken payload never blocks. Stop gate: blocks once while lint reports errors and never when a stop hook is already active. Session start prints the brief. (3) Git gates: pre-commit runs lint and the continuity codes only when `git.require_lint_pass` is true; commit-msg accepts a type from `git.commit_types` (merge, revert, fixup, squash and amend messages pass); both keys are now read by code, and `git.co_author` was removed. (4) Neutrality: franchise vocabulary lives only in `Meta/Presets/`; a test scans the template outside presets for franchise tokens and personal paths; the art-concept skill takes its visual identity from the vault's design sheet. (5) Skills: valid frontmatter, a name equal to the folder, a description containing `Use when`, identical in `.claude` and `.agents`; `narr doctor` reports violations as "Agent Skills". (6) Memory: `session close` refreshes only the "Current Objective" and "Last Updated" sections of `hot.md`; the brief shows the last three lessons; curator decisions live in `memory/decisions/` (`narr decide`) and this ledger records the framework's architecture. (7) Consistency: costs and limitations cite Sanderson's Second Law; the scope list in `Meta/Scope_Profiles.md` equals the configured hierarchy plus `meta`; Rule 10 lists every prefix used by blueprints, the zone map and the files; the Canonical Hierarchy of Truth is defined once, in the conflict-arbitration skill, and `CONVENTIONS.md` points to it.
- **Consequences:** After `narr hook install`, an agent can no longer silently edit a frozen source, and a commit with an unknown type or lint errors is refused. A vault that wants no gate sets `git.require_lint_pass: false` or runs `narr hook uninstall`. Rules that still say "Antigravity" or other harness names describe real tools, not personal configuration. Residual risk, accepted: hooks need `narr` on the path of the agent and git processes; the stop gate trusts the agent's `stop_hook_active` flag; the pre-write guard covers the file-writing tools only, not shell commands.

## ADR-022: Craft and Editorial Intelligence — Advisory Prose Metrics, Computed Continuity Checks, Rubric Skills
- **Status:** Accepted (2026-10-22). Builds on ADR-017 (check-code registry), ADR-020 (manuscript markers) and ADR-021 (skills validation); contradicts no earlier ADR.
- **Context:** Research into sixteen public craft sources and skill collections (summarised in `docs/workflow/area-9-research/`) found that the framework verified structure but not craft: nothing measured prose in Portuguese or Spanish, the foreshadowing check was a substring grep for the word "overdue", gaps in the chapter numbering, near-empty final chapters and a dead character listed in a later cast went unnoticed, and the craft skills were thin.
- **Decision:** (1) `narr.prose` measures a chapter's narration (dialogue in dash, straight, curly and guillemet forms, code, comments, headings and frontmatter removed): sentence rhythm, filter-word and -mente densities, the longest run of identical sentence openers, negative parallelisms and stock phrases, for `pt-BR` and `es`; `narr stats <N>` reports them and `prompt validate` adds them to its metrics. (2) Five warning-only lint codes use them, tuned by a `style:` block in `vault.yaml` with an `enabled` switch: STY001 filter density, STY002 adverb density, STY003 flat rhythm, STY004 repeated openers, STY005 stock phrases and negative parallelism; they apply only to chapters under `04_Manuscript/**/Chapters/`. (3) `narr.ledgers` parses markdown tables; the foreshadowing and Chekhov ledgers are checked by FSH001 (error: payoff before plant), FSH002 (error: paid off or discharged with no payoff chapter) and FSH003 (warning: planted with no plant chapter); VAL028 now fires (warning) for an unresolved row whose intended target chapter is already drafted, and no longer for the word "overdue". (4) MSC005 (warning) reports gaps in the pt-BR chapter numbers, MSC006 (warning) reports a review, final or published chapter under `style.min_chapter_words`, and CHR001 (error) reports a character with `died_in` listed in the `characters:` cast of a later chapter unless `revived_in` is at or before it. (5) Six new skills (scene-audit, reader-sim, revision-pass, narrative-architecture-audit, sandbox-diverge, unblock) and five extended ones (story-arc, tone-and-voice-audit, foreshadowing-audit, continuity-postmortem, write-chapter), plus two checklists and a sources page in `05_Craft_and_Feedback/Checklists/`, all in the framework's own words with credit given; review skills never edit prose, the divergence skill writes only sandbox notes and the unblock skill writes nothing.
- **Deferred (kept in the dossiers, not built):** a scene ledger and `narr scenes`; termbase-density (idea budget) warnings; age arithmetic; era and anachronism lists; watch-spellings; an inline-note convention; a derived-voice report; an audit cache; skill regression evals with graders; EPUB export; a dialogue-convention lint (the curator's quotes-versus-dash decision is still pending); genre obligatory-moments presets.
- **Consequences:** Existing manuscripts may show new warnings; `narr lint --strict` turns them into failures, `style.enabled: false` silences the prose ones. FSH001 and FSH002 are errors because they describe impossible ledger states. Residual risk, accepted: the lexicons are short plain-word tables, the negative-parallelism pattern is a heuristic, dialogue detection depends on the dash or quote marks being used, and sentence splitting is naive around abbreviations.

## ADR-023: Distribution Integrity — Trusted Publishing, Pinned Toolchain, One Version One Build, Safe Sync and a Real Upgrade
- **Status:** Accepted (2026-10-22). Builds on ADR-003 (one CLI) and ADR-021 (framework-owned agent files); contradicts no earlier ADR.
- **Context:** An independent audit of the release chain found that the publish workflow, started by `workflow_run`, accepted a pull request from a fork whose branch was called main and ran it next to the deploy key; that every third-party action was referenced by a mutable tag; that verification never built the wheel and ran one Python version although the floor is 3.11; that the dev toolchain and build backend were not pinned and a `vector` extra advertised code that did not exist; that a version could be republished with different content; that the template sync emptied its target after a single path check; and that `narr upgrade` could neither refresh framework files nor keep edited ones, although its documentation and the update workflow said it did.
- **Decision:** (1) The publish job runs only for `workflow_dispatch` or for a successful `workflow_run` whose event is `push` and whose head repository is this repository. (2) Every `uses:` in every workflow of the repository, of the template repository (`docs/vault-template`) and of vaults (`template/.github`) is pinned to a 40-character commit hash with its tag in a comment; the only exceptions are local workflows and the curator's own reusable update workflow; a static test parses the files and enforces both rules. (3) Verification runs on Python 3.11 and 3.12 on Linux and Windows, builds the wheel without build isolation (the backend is pinned), checks its inventory and installs it into a clean environment where `narr --version` and `narr doctor --vault template` must succeed (`scripts/smoke_wheel.py`, shared with the publish job). (4) `constraints.txt` holds exact pins for the runtime, the dev tools, the build tools and the render extra with their dependencies; a test requires an exact pin for every direct dependency of every extra and for every installed transitive dependency; the unimplemented `vector` extra is removed (ADR-019: retrieval is lexical). (5) `publish_dist.py` reads the recorded `LATEST.json`: the same wheel again is a no-op, a lower version is refused, and the same version with a different wheel is refused with a request to bump the version. (6) `sync_vault_template.py` refuses a target that overlaps this checkout, is not a git checkout (unless an empty folder with `--init`), lacks the template markers, or has uncommitted changes (unless `--allow-dirty`); `--dry-run` prints the plan; local and generated files (`__pycache__`, `.narr`, SQLite files) are never published; the published skeleton carries `.narr-manifest.json`. (7) `narr upgrade --from <template checkout>` compares each framework-owned file (`.agents` and `.claude` rules and skills, `.claude/settings.json`, `.githooks`) with the skeleton and the committed manifest: a missing file is added, an identical file is current, an unedited file (equal to what the last upgrade delivered) is updated, and any other file is kept exactly as it is and reported as `kept`; line endings alone are not edits; nothing outside those paths is touched; skeleton links are ignored. Without `--from` the command only syncs the agent mirrors and the version stamp and says so. The update workflow passes `--from`.
- **Open curator decisions (not made here):** the licence of `narr` and the template; the next version number, because the CHANGELOG's unreleased section describes a large change under the already published 2.2.0 (the new publish guard will refuse that wheel until the version is bumped). Pushing, tagging and publishing remain CI or manual acts.
- **Consequences:** A fork cannot reach the deploy key through the publish workflow; a moved tag cannot change a build; CI proves the wheel installs and runs before release; two different builds can no longer share a number; the sync cannot empty an unrelated folder; vaults can pull framework updates without losing edits, and a vault from before the manifest keeps every differing file on its first upgrade. Residual risk, accepted: action hashes go stale until someone refreshes them deliberately; removal of a framework file upstream is not propagated to vaults; the reusable update workflow is still referenced by the moving tag `stable` of the curator's own repository.

## ADR-024: CLI Contract — Strict `--vault`, `--json` Everywhere, One Error Model, Shared Gates
- **Status:** Accepted (2026-10-22). Builds on ADR-003 (one CLI) and ADR-016 (one path gate); contradicts no earlier ADR.
- **Context:** An audit of the 48 commands found that four could not be pointed at a vault; that an explicit `--vault` silently resolved to an enclosing vault, so a typo operated on another vault; that seventeen commands had no `--json`; that with `--json` a failure was still red text on standard error; that an unwritable `--output` printed a Python traceback; that `crosscheck` and `pipeline run crosscheck` (and `lint` and `pipeline run lint`) were two implementations with different output; that `narr new chapter_pt` and `narr chapter new` followed different rules so one chapter number could get two files; and that help texts cited ADR numbers that do not exist or mean something else.
- **Decision:** (1) An explicit `--vault` must itself be a vault root (it contains `vault.yaml` or a `.narr` folder); otherwise the command fails with "is not a narrative vault". Without `--vault` the search upwards from the working directory and the `./template` fallback stay. (2) Every command takes `--vault` except `version`, and `--json` except `hook run`, which speaks the agent hook protocol; the exemptions live in one table in the contract test, with the reason, and a new command must carry both options or be added there. (3) One `fail()` helper reports every expected failure: a body `{"status": "error", "error": ...}` on standard output under `--json`, otherwise one `Error: ...` line on standard error; exit code 1, never a traceback. Known I/O failures (an unwritable `--output`, a failed import or rename) go through it. The console script and `python -m narr` run `main()`, which turns any other exception into `Error: unexpected failure (Type: message)` with exit 1 (a JSON body under `--json`); `NARR_DEBUG=1` lets the exception through with its traceback. Typer's own usage errors keep exit 2. (4) `lint`, `crosscheck` and their `pipeline run` forms share one evaluation each, so they agree on findings and exit code; `pipeline run` gains `--json` with `{"step", "passed", ...}`. Gate failures that already print their result body (`narr eval --min-recall`, `ingest close`) keep that body. (5) `create_page` for `chapter_pt` and `chapter_es` refuses a chapter number that already has a file, using the lookup rule of ADR-020, so both scaffolders agree. (6) Success bodies: action commands print `{"status": "ok", ...}` with paths and ids; `brief` prints `{"brief"}`; `rag context` prints `{"chapter", "context"}`; `prompt list` prints the actions; `pipeline plan` prints the phases; `version` prints `{"version"}`. (7) ADR citations in the source point at ADRs that exist and match the topic; a test checks both.
- **Deferred:** splitting `cli.py` by command group; a global `--quiet`; shell completion; renaming command groups.
- **Consequences:** An agent can address any command to a vault without depending on the working directory, can parse every result, and can tell a failure from an empty result. A typo in `--vault` is an error instead of a silent action on another vault. Scripts that passed a folder inside a vault as `--vault` must now pass the vault root. The aliases (`capture` and `ingest capture`, `chapter` and `manuscript`, `memory brief` and `session brief`) remain aliases of one implementation.
